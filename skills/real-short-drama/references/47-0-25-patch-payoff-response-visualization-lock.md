## 0.25 PATCH：PAYOFF RESPONSE VISUALIZATION LOCK

### 爽点反应可视化锁

【补丁目的】

修复以下问题：

1. 主角亮身份 / 亮证据 / 亮旧账后，反派只说“怎么可能”，缺少视觉崩塌。
2. 爽点只靠主角台词完成，没有对手接不住的画面。
3. 观众没有看到权力关系改变，只听到了信息。
4. 反派反应重复、空泛、没有递进。
5. 爽点缺少被羞辱者的情感回报镜头。

从本补丁生效起，每个核心爽点后必须安排 `PAYOFF RESPONSE BEAT`。

### 一、核心原则

爽点不是主角说完。  
爽点是对方接不住。

每次核心反击后，必须让观众看到：

```text
谁的权力塌了？
谁的表情变了？
谁不敢继续说话？
谁开始害怕？
谁终于被看见？
```

### 二、PAYOFF RESPONSE BEAT 模板

每个爽点后必须填写：

```text
PAYOFF RESPONSE BEAT

Payoff Trigger:
主角刚释放了什么信息 / 证据 / 身份？

Primary Target Reaction:
被打击对象的第一反应。

Secondary Reaction:
旁观者 / 亲属 / 群众 / 未婚夫 / 下属的反应。

Protected Person Reaction:
被羞辱者 / 被保护者的情感回报。

Power Shift Visual:
画面如何表现权力转移？

Silence Beat:
是否有 0.5–1.5 秒沉默？

Next Pressure:
反派如何否认、狡辩、升级，或被迫沉默？
```

### 三、反应类型库

允许使用：

```text
酒杯停在半空
手指发抖
椅子后退摩擦地面
笑容僵住
嘴角抽动
眼神闪避
低头不敢看证据
未婚夫松开手
亲戚低语突然停下
佣人停止动作
公公第一次开口阻止
婆婆从坐姿变成站起
旁观者交换眼神
被羞辱者含泪抬头
主角把证据推近，对方不敢碰
```

禁止只写：

```text
震惊
惊呆了
不敢相信
全场哗然
大家都愣住
```

必须具体化。

### 四、反应递进规则

如果一集有多个爽点，反应不能重复。

推荐递进：

```text
第一层身份反击：
反派轻微僵住，但试图维持体面。

第二层证据反击：
关键当事人手部失控，旁观者开始沉默。

第三层旧账反击：
反派失去话语权，开始阻止主角继续说。

第四层悬念追击：
被羞辱者情感回弹，反派彻底不敢接证据。
```

禁止连续三次：

```text
反派震惊。
反派更震惊。
反派彻底震惊。
```

### 五、SHOT UNIT 规则

每个核心爽点后，至少需要一个以下镜头：

```text
1. Target Reaction Close-up
2. Protected Person Reaction Close-up
3. Prop + Reaction Same-Frame
4. Silence Beat Power Frame
5. Crowd Low-Depth Reaction
```

如果时长不足，可以把反应整合进同一个连续镜头：

```text
证据在前景，反派手抖在背景；
被羞辱者在画面边缘抬头；
不切镜，只用焦点转移和慢推近。
```

### 六、输出前自检

- 每个爽点后是否有反派反应？
- 反应是否具体，而不是“震惊”？
- 被羞辱者是否有情感回报镜头？
- 权力变化是否可视化？
- 是否有沉默拍？
- 多个反应是否有递进？
- 是否避免重复“怎么可能”？
- 是否让观众看到“这巴掌打回去了”？

### 七、口诀

爽点不是说出来，是砸到脸上。  
反派接不住，观众才爽。  
不要写震惊，要写手抖、杯停、笑僵、椅退。  
每次打脸，都要有回声。

### 五层架构

改一层不应改写另一层，层间只通过结构化引用沟通。

Layer 1 叙事 —— 故事 / 对白 / 结构 / 爽点设计（唯一真相·上游）  
Layer 2 运行时 —— 角色状态 / 世界状态 / 剧集状态（驱动下一集，§3）  
Layer 3 资产 —— 世界视觉设定板 / 角色基准图 / 角色卡 / 道具 / 场景 / 音乐主题 + 参考（生产真相，§4）  
Layer 4 编译器 —— 图像 / 视频 / 音乐 prompt 由对象编译而来（一次性产物，§6）  
Layer 5 原生视频音频与最终 BGM 边界 —— Native Video Audio / 中文对白 / OS / 环境声 / 必要音效 / Voice Registry / no TTS; native audio + optional final BGM（默认让视频直接可用，§6.5）

### 单向流（带生产阶段）

叙事 → 运行时 → 世界视觉设定板 → 角色白底三视图全身基准图 → 资产（角色卡 / 地点 / 道具 / 服装） → 分镜（整合） →〈闸门〉关键帧图 →〈闸门〉顺序 I2V 视频 + 原生中文对白/OS →〈闸门〉原生音频失败则修 SHOT UNIT 并重生成 → 成片

下游不能改写上游：

- 成片改不了 prompt 意图
- prompt 改不了资产
- 资产改不了剧情

要改就回上游改、往下重编。

这是一条要逐阶段往下推、带 go/no-go 闸门的生产线（见 §6.6），不是一次把文字吐完就停。实际的出图 / 出视频 / 合成发生在你接的工具里（生图器 / Seedance / 剪辑程序），skill 负责驱动每个阶段并在闸门停下确认。
