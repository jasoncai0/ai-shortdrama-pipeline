# Version history

> **v0.1.2 变更说明（@sheet MODULE 03 = 紧凑三视图，治「整图变成一排重复站姿」）**：把 `MODULE 03` 从 v0.1.0/v0.1.1 的「BASE APPEARANCE INHERITANCE / 纯文字标签 / 5–8% / 不渲染角色 / 禁止 front-side-back」整体回调为 `MODULE 03 — COMPACT BASE TURNAROUND（紧凑三视图身份继承区）`。修正实际症状:用户需要 @sheet 内**保留**一个三视图来锁「这是同一个人」,而不是禁止三视图;但又不要整张 sheet 塌缩成一排几乎一样的全身站姿。新规则:①Module 03 允许 front / 3-4 / side / back 全身转面(可含 height scale),继承 confirmed @base 的脸 / 骨相 / 发型 / 身材 / 服装;②但转面只占中上方约 20-25%,**不得撑满整张图**,表演模块 05-11 合计必须占据大部分版面;③明确「身份一致 ≠ 姿势一致」:同一张脸贯穿全图,但每个表演格必须各自不同的表情 / 角度 / 姿态 / 动作,禁止把转面站姿复制进 05-11,禁止整张 sheet 变成一排重复站姿;④失败判定与门禁同步:转面撑满全图、整图重复站姿、05-11 被做成第二组正侧背队列均判失败;⑤同步重写 §五 Module 03 定义、§六 Prompt Anchor、§七 Negative Anchor、§九/§十一 门禁与失败判定、§14 版面与编译 prompt 模板、补丁口诀及相关一行式描述。**核心原则:@sheet 里可以有三视图,但它只是中上方一个紧凑身份区;整张图必须是「同一个人 + 各异表演」,不是「同一个人 + 重复站姿」。**

> **v0.1.1 变更说明**：把角色设计阶段重构为 `CHARACTER ASSET PACKAGE` 复合阶段，内部顺序固定为 `CHARACTER FUNCTION MAP → CHAR_xxx@base_stage → BASE CONFIRMATION GATE → CHAR_xxx@sheet → SHEET CONFIRMATION GATE`。`@base` 必须先真实生成并获得用户确认 / `user_confirmed=yes`，否则不得生成 `@sheet`；但对主角 / 重要角色而言，角色资产包只有在 `@sheet` 也确认后才算完成，避免系统停在 base。全局删除 `@sheet` 里的“视角队列 / 正侧背队列 / 多阶段身份矩阵”等诱导词，统一改为“头部角度 / 姿态 / 近景 / 手部 / 服装等表演辅助图块”。同时将 `@sheet` 拆成两层：AI 生图层只生成无准确文字依赖的人物图块、表情、姿态、服装、手部和无字色块；准确角色 ID、姓名、年龄、base image_id、node_key、设计备注等全部由后期模板覆盖层生成，禁止要求生图模型直接生成可读资料卡文字。**BASE 必须确认后才能做 SHEET；SHEET 不复刻 BASE；SHEET 文字由模板层负责。**

> **v0.1.0 变更说明**：全局刷新 `@base → @sheet` 规则。`@base` 继续作为最高优先级角色身份真相源；`@sheet` 不再围绕“身份重建 / 站姿队列 / 基准图复刻”编译，而只基于已确认 `@base` 继承同一张脸、发型、身材比例、年龄感、服装轮廓、皮肤真实感与整体身份气质。`MODULE 03` 统一改为 `BASE APPEARANCE INHERITANCE`，只记录“本 sheet 参考哪个 base 的形象”，不再承担任何身份重建任务。核心原则升级为：**BASE 锁身份；SHEET 继承 base 形象并扩展表演、情绪、头部、姿态、近景、服装材质与手部动作。**

> **v0.0.1 变更说明**：在 v34「节奏完整性修正版」基础上，清除全文残留的旧硬性 KPI，使其与顶层 §0.1K / §0.1L / §0.1M（戏剧优先、对白完整不切碎、镜头数量只做软区间诊断）完全一致。具体对齐：① 删除各处 `dialogue max 8s` / `Longest Dialogue Shot <= 8s` 对白硬上限，改为完整句块优先、时长视戏而定；② 把 `MICRO_SHOT_UNIT Count 28-45` 等硬数量改为软区间诊断（90s 参考 20–38、60s 参考 14–26）；③ 把 `Hard Cut Count >= 20` 改为仅参考、不单独判失败；④ 把"12 个长镜头 = 直接失败"重述为"无表演支撑的呆板长镜头 = 失败"，判罚依据是戏而非数量；⑤ §7.2 自检改为质化戏剧检查，仅保留结构性失败项；⑥ §0.43 素材密度锁同步对齐。保留的合理技术约束：VIDEO_GENERATION_TASK 6-15s/max 18s 的 Seedance 提交边界、素材冗余 135–180s 目标、工具调用按 task 计数。

> **v0.0.2 变更说明**：新增 `0.1N STORY FRAMEWORK BEFORE VISUAL BIBLE LOCK / 剧本框架先于世界视觉设定板锁` 与 `0.1O PRODUCTION FILE CONTRACT & CANVAS WRITEBACK LOCK / 生产文件契约与画布写回锁`。修正 v0.0.1 中“WORLD_VISUAL_BIBLE 过早进入”的流程风险：世界图仍然是第一张视觉资产，但不再是第一步生产动作；在生成 WORLD_VISUAL_BIBLE 前，必须先完成 STORY_FRAMEWORK_LOCK、SERIES_ENGINE / PAYOFF_LADDER、EP01_DRAMA_BEAT_LOCK 与 CHARACTER_FUNCTION_MAP。新增文件沉淀机制：凡会被后续 agent / skill / prompt compiler / 视频任务引用的内容，必须先写入稳定 `.md` 文件或 Canvas 文件块；对话正文、临时解释、未写盘 prompt 不得作为下游生产真相源。核心原则改为：先锁戏，再出图；先写盘，再继承；世界图服务剧情，不反向绑架剧情。

> **v0.0.3 变更说明**：新增 `0.1P WRITEFILE CANVAS NODE_KEY PERSISTENCE LOCK / WriteFile 真实 Canvas 文本节点持久化锁`。进一步修正 v0.0.2 中“Markdown 文件块 / Canvas 文件块模拟写盘”仍可能被误判为真实沉淀的问题：所有脚本、框架、分镜、关键帧说明、视频任务、EDL 与状态快照等文本型生产产物，必须通过 `WriteFile` 创建真实 Canvas 文本节点，并获得 `node_key` 作为持久化凭证。没有 `node_key`，不得声称已写盘、不得标记阶段完成、不得进入后续分镜 / 视频任务 / EDL。核心原则升级为：`WriteFile` 创建节点，`node_key` 证明持久化；Markdown 只是预览，不是生产真相。

> **v0.0.4 变更说明**：新增 `0.1Q MANDATORY PREDECESSOR NODE CONSUMPTION GATE / 强制前置节点消耗门禁`。进一步修正 v0.0.3 中“已经要求 WriteFile / node_key，但下游阶段仍可能不检查前置节点就继续生产”的执行风险：任何 SHOT_KEYFRAME / VIDEO_GENERATION_TASK / I2V 等下游阶段进入前，必须列出 Required Predecessor Nodes，并逐项检查真实 `node_key`。用户要求“继续 / 下一张 / 生成关键帧 / 开始视频”不等于授权跳过 LOCATION / PROP / SCENE BREAKDOWN。缺少 `assets/locations.md node_key`、`assets/props.md node_key`、`storyboards/EP001_storyboard.md node_key` 等必要前置节点时，必须阻断并回到缺失阶段；内容生产流畅感不得覆盖流程门禁。核心原则升级为：先查 `node_key`，再做内容；没有前置节点，不进下游。

> **v0.0.5 变更说明**：新增 `0.1R CHARACTER BASE PRIMARY REFERENCE & 11-MODULE CHARACTER SHEET AUXILIARY LOCK / 角色 Base 主参考与 11 模块 Character Sheet 辅助参考锁 / @sheet 只继承 @base 形象锁`。修正系统把“完整角色图 / character sheet / 角色一致性图”错误理解为再次生成纯 base 身份参考图的问题：`CHARACTER BASE` 继续保持白底三视图全身身份基准图，是 keyframe / I2V 的最高优先级主参考；`CHARACTER SHEET` 是在 Base 确认后生成的 11 模块多宫格辅助参考图，用于表情、微表情、头部角度、姿态、电影近景、服装拆解和手部动作。核心原则升级为：BASE 锁身份，SHEET 补表演；视频优先喂 BASE，SHEET 不得单独作为 I2V 主参考。

> **v0.0.6 变更说明**：新增 `0.1S KEYFRAME REFERENCE INPUT MANIFEST & NO SELF-INVENTED VISUAL ASSET LOCK / 关键帧生图引用输入清单与禁止自造视觉资产锁`。修正关键帧 / 视频生成阶段“只写 CHAR_ID / LOC_ID / 文字 prompt，但没有实际传入已确认图片参考”的漏洞：任何 SHOT_KEYFRAME 生图前必须输出 `KEYFRAME REFERENCE INPUT MANIFEST` 与 `IMAGE GENERATION TOOL CALL CARD`，逐项检查并实际附带已确认 `CHARACTER BASE image_id`、`LOCATION image_id`、剧情关键 `PROP image_id`、必要 `COSTUME / FORM image_id`；`CHAR_ID`、`LOC_ID`、文字描述、World 图风格锚点均不能替代 confirmed reference image input。核心原则升级为：先引用，再生图；Base 不进工具，人物必漂；Location 不进工具，场景必跳；没有 reference input，就没有 keyframe。

> **v0.0.7 变更说明**：新增 `0.1T VIDEO START FRAME ≠ IDENTITY REFERENCE NODE LOCK / 视频首帧不等于身份参考节点锁`。修正执行层把 `start_frame_image_node` 误当作 `reference_nodes` 的问题：关键帧首帧只负责构图、动作起点和首帧画面，不负责整段视频的人脸、身材、服装、场景、道具一致性。任何 `generate_video / I2V` 调用前必须输出 `VIDEO TOOL CALL CARD`，并强制 `reference_nodes` 同时包含所有出镜角色的 confirmed `CHARACTER BASE node_key`、当前 `LOCATION node_key`、剧情关键 `PROP node_key`、必要 `COSTUME / FORM node_key`；缺任一项则 `Can Call Tool = NO`，不得调用视频工具。核心原则升级为：首帧不是身份锁；Base 必须进入 reference_nodes；没有 Video Tool Call Card，就没有视频调用。
