## v34 修订说明

v34 在 v31 的严格流程状态机、禁止自主跳步、多形态串行确认锁，以及 v30 的可剪素材密度、硬切素材包、精选片段 EDL 与跨集资产记忆锁基础上，新增两个视觉执行硬锁：

1. `0.1C WORLD_VISUAL_BIBLE DIRECT VISUAL RESULT LOCK`：WORLD_VISUAL_BIBLE 阶段不得只输出文字描述、九宫格说明、色彩表或生图 prompt；支持图像生成时必须直接生成一张完整 16:9 横版 3×3 结构化世界视觉设定板，并提取 WORLD_VISUAL_MODULES。
2. `0.1D CHARACTER IDENTITY BASE DIRECT THREE-VIEW FULL-BODY RESULT LOCK`：CHARACTER IDENTITY BASE 阶段唯一合法图像结果是一张白底 / 浅灰底三视图全身基准图，包含同一角色 front / side / back 三个完整全身视图；严禁角色资料卡、reference sheet、信息栏、局部细节拼版、文字标签、表情宫格、场景背景或半身肖像。

v34 保留两个强制门禁：

1. `0.1E FIRST VISUAL STYLE BOARD MANDATORY START LOCK`：所有项目第一张视觉资产必须是 WORLD_VISUAL_BIBLE。没有世界风格板，不得生成角色、地点、道具、分镜、关键帧或视频 prompt。
2. `0.1F GENERATED IMAGE REQUIRED GATE LOCK`：任何直接生图确认阶段没有实际生成图片，不得进入下一步。Prompt、文字方向、Image Task、用户确认文字都不能替代生成图像。

v34 保留三视图真人感与无字硬锁：

1. `0.1G THREE-VIEW NO-TEXT PHOTOREAL STUDIO BASE LOCK`：CHARACTER IDENTITY BASE 三视图允许存在，但图像内绝对禁止任何文字、标签、姓名、身份栏、FRONT/SIDE/BACK 标注；三视图必须像真人棚拍 / 服装试装参考，而不是游戏角色设定稿、CG 转面图或服装概念图。

v34 镜头生产核心重构：

1. `0.1H SHOT UNIT SEMANTIC RESTRUCTURE & BATCHED KEYFRAME VIDEO TASK LOCK`：全局废止旧版 SHOT UNIT 语义；SHOT UNIT / MICRO_SHOT_UNIT 只能表示碎镜头剪辑单位，VIDEO_GENERATION_TASK 才表示一次视频生成提交；多个碎镜头通过 BATCH KEYFRAME SEQUENCE 批量跑视频，最终 SELECTS EDL 必须按 MICRO_SHOT_UNIT 硬切。
2. `0.1I BATCHED KEYFRAME PRODUCTION ACCEPTANCE GATE`：强制 MICRO_SHOT_UNIT、SHOT_KEYFRAME、VIDEO_GENERATION_TASK、BATCH_KEYFRAME_SEQUENCE、SELECTS_EDL 五层同时输出；缺少任一层不得进入 I2V。
3. `0.1J VIDEO TASK TOOL CALL CARDINALITY LOCK`：强制视频生成工具调用按 VIDEO_GENERATION_TASK 计算，不按 MICRO_SHOT_UNIT 计算；一个 task 调用一次工具、输出一个视频文件，视频内部包含多个 micro shot 分镜段落。
4. `0.1K DIALOGUE SENTENCE BLOCK LOCK`：镜头可以碎，但对白必须先以完整中文语义句块锁定；MICRO_SHOT_UNIT / VIDEO_TASK / SELECTS_EDL 不得切碎核心台词。
5. `0.1L MICRO_SHOT_UNIT COUNT SOFT RANGE & DRAMA INTEGRITY LOCK`：废止固定 unit 数量硬 KPI，改为软区间诊断；最终验收以对白完整、戏剧完整、可剪辑和信息密度为准。
6. `0.1M NARRATIVE RHYTHM INHERITANCE LOCK`：底层 micro shot / video task / EDL 必须继承上游 hook、pressure curve、payoff、cliffhanger，不得重新编剧或切碎 beat。
7. `0.1N STORY FRAMEWORK BEFORE VISUAL BIBLE LOCK`：WORLD_VISUAL_BIBLE 是第一张视觉资产，但不得早于剧本框架；必须先锁 STORY_FRAMEWORK、SERIES_ENGINE / PAYOFF_LADDER、EP01_DRAMA_BEAT 与 CHARACTER_FUNCTION_MAP，再进入世界视觉设定板。
8. `0.1O PRODUCTION FILE CONTRACT & CANVAS WRITEBACK LOCK`：所有后续会被引用的故事、资产、脚本、分镜、关键帧、视频任务、EDL 与状态快照，必须沉淀为稳定 `.md` 文件或 Canvas 文件块；下游只能读取文件化生产真相源，不得依赖上一轮对话记忆重新发明。
9. `0.1P WRITEFILE CANVAS NODE_KEY PERSISTENCE LOCK`：所有脚本、框架、分镜等文本型生产产物必须通过 `WriteFile` 创建真实 Canvas 文本节点，并获得 `node_key` 作为持久化凭证；没有 `node_key`，不得被后续分镜 / 视频任务合法引用。
10. `0.1Q MANDATORY PREDECESSOR NODE CONSUMPTION GATE`：任何下游阶段进入前必须先列出并检查 Required Predecessor Nodes；没有必要前置 `node_key`，不得进入 SHOT_KEYFRAME / VIDEO_GENERATION_TASK / I2V；用户“继续”不等于跳过 LOCATION / PROP / SCENE BREAKDOWN。
11. `0.1R CHARACTER BASE PRIMARY REFERENCE & 11-MODULE CHARACTER SHEET AUXILIARY LOCK`：`CHARACTER BASE` 继续作为白底三视图主身份参考，优先级最高；`CHARACTER SHEET` 作为 11 模块多宫格辅助参考，必须在 base 确认后生成，补充表情、姿态、近景、服装拆解和手部动作，但不得替代 base。
12. `0.1S KEYFRAME REFERENCE INPUT MANIFEST & NO SELF-INVENTED VISUAL ASSET LOCK`：关键帧 / 视频任务不得只引用 `CHAR_ID / LOC_ID / PROP_ID` 或文字 prompt；必须在生图 / I2V 前生成 Reference Input Manifest 与 Tool Call Card，并实际传入已确认 Base、Location、Prop、Costume/Form 图片资产。
13. `0.1T VIDEO START FRAME ≠ IDENTITY REFERENCE NODE LOCK`：视频工具调用时强制拆分 `start_frame_image_node` 与 `reference_nodes`；关键帧首帧不得替代角色 Base / 场景 / 道具 / 服装参考节点，缺少 `VIDEO TOOL CALL CARD` 或缺少 confirmed reference node_key 时不得调用 `generate_video / I2V`。

v31 原有上游控制补丁：

1. `0.43 EDITABLE FOOTAGE DENSITY & HARD-CUT MATERIAL LOCK`：把生产目标从“刚好生成最终成片时长”改为“生成可剪素材包”，默认 60s 成片生成 90–120s 素材，允许剪掉 25–40% 水分后仍够发布。
2. `0.44 SELECTS EDL & CUTDOWN ASSEMBLY LOCK`：强制每集输出素材精选表、可剪入点/出点、保留/可丢弃段落、硬切组装建议，避免生成 100s 素材后仍没有剪辑结构。

v34 的核心变化：

```text
SKILL = STRICT PIPELINE STATE MACHINE
NO AUTONOMOUS STAGE JUMP
ONE CHARACTER → ONE WHITE-BACKGROUND THREE-VIEW FULL-BODY BASE (PRIMARY) → ONE CONFIRMED BASE IDENTITY → ONE 11-MODULE CHARACTER SHEET (SECONDARY AUXILIARY) → ONE FORM AT A TIME
MICRO SHOT UNIT → SHOT KEYFRAME → KEYFRAME REFERENCE INPUT MANIFEST → BATCHED VIDEO GENERATION TASK → SELECTS EDL
MICRO_SHOT_UNIT 要碎，VIDEO_GENERATION_TASK 可以打包，EDL 按 MICRO_SHOT_UNIT 剪
DIALOGUE_SENTENCE_BLOCK 先锁完整台词，再拆 MICRO_SHOT_UNIT
MICRO_SHOT_UNIT Count 是软区间诊断，不是硬 KPI
底层镜头必须继承上游叙事节奏，不得重写或切碎 beat
STORY_FRAMEWORK 先于 WORLD_VISUAL_BIBLE
WORLD_VISUAL_BIBLE 是第一张视觉资产，不是第一步生产动作
PRODUCTION_FILE_CONTRACT 是下游继承真相源
任何可继承文本内容必须通过 WriteFile 创建真实 Canvas 文本节点
WriteFile 是真实 Canvas 写回动作
node_key 是唯一持久化凭证
NO node_key, NO downstream inheritance
先锁戏，再出图；先 WriteFile，再继承；先引用 confirmed image，再生成 keyframe；世界图服务剧情，不反向绑架剧情
FINAL_RUNTIME_TARGET ≠ GENERATED_FOOTAGE_RUNTIME
素材不是成片。
素材是给后期剪的。
每一秒必须有信息；没信息就必须可剪掉。
```

```text
必须输出 MICRO_SHOT_UNIT LIST、SHOT_KEYFRAME LIST、KEYFRAME REFERENCE INPUT MANIFEST、IMAGE GENERATION TOOL CALL CARD、VIDEO_GENERATION_TASK PLAN、BATCH_KEYFRAME_SEQUENCE、SELECTS_EDL BY MICRO_SHOT_UNIT。

- Tool Call Unit = VIDEO_GENERATION_TASK
- MICRO_SHOT_UNIT is not a tool call
- 1 VIDEO_GENERATION_TASK = 1 video generation tool call = 1 output video file
- Output video contains multiple internal micro-shot segments

```
