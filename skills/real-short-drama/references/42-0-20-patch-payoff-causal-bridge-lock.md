## 0.20 PATCH：PAYOFF CAUSAL BRIDGE LOCK

### 爽点因果桥锁

【补丁目的】

修复以下问题：

1. 单集里堆多个爽点，但爽点之间没有因果关系。
2. “亮身份 / 亮资产 / 亮旧账 / 亮证据 / 亮人脉”像并列信息通知，而不是连续打脸。
3. 主角能力、反派命门、被羞辱对象、旧账之间没有绑定。
4. 爽点看起来很多，但观众感到“硬塞设定”。
5. 反击不能精准回应前面的羞辱点。

从本补丁生效起，每个核心爽点释放前，必须建立 `PAYOFF CAUSAL BRIDGE`。

### 一、核心原则

爽点不能孤立存在。

每个爽点必须回答：

```text
它为什么现在出现？
它打的是谁的脸？
它回应了前面哪一句羞辱？
它改变了哪一层权力关系？
它如何推动下一个爽点？
```

如果回答不了，这个爽点不能进入本集。

### 二、PAYOFF CAUSAL BRIDGE 模板

每个核心爽点必须填写：

```text
PAYOFF CAUSAL BRIDGE

Payoff ID:
Payoff Type:
- identity / wealth / power / evidence / relationship / old_debt / medical / legal / business / family_secret / revenge

Previous Humiliation:
前面哪个具体羞辱动作或台词制造了这个爽点的需求？

Emotional Debt:
观众为什么期待这一刀打回去？

Causal Trigger:
是什么动作 / 台词 / 道具触发主角释放这个爽点？

Power Target:
这个爽点打击的是谁？婆婆 / 老板 / 未婚夫 / 反派家族 / 群体 / 旧账当事人？

Power Reversal:
释放前谁掌控？释放后谁掌控？

Concrete Proof:
这个爽点是否有物证、行为证据、第三方反应、身份验证或当事人失态承接？

Next Payoff Hook:
它如何引出下一个爽点？
```

### 三、爽点链规则

一集内多个爽点必须形成链条：

```text
羞辱点 A
→ 反击点 A
→ 反派否认 / 升级
→ 证据点 B
→ 当事人失态
→ 更大旧账 / 悬念 C
```

禁止：

```text
羞辱
→ 我是医生
→ 我很有钱
→ 你们欠我家钱
→ 我还有欠条
```

这种是并列堆设定，不是因果链。

### 四、常见因果桥类型

#### 1. 身份桥

```text
反派羞辱主角没资格
→ 主角亮出更高资格
```

#### 2. 关系桥

```text
反派羞辱某人无关紧要
→ 主角证明此人是自己的核心亲人 / 恩人 / 底线
```

#### 3. 旧账桥

```text
反派炫耀今天的体面
→ 主角揭露这份体面来自被羞辱者
```

#### 4. 命门桥

```text
反派正在求某种资源
→ 主角正是资源掌控者
```

#### 5. 证据桥

```text
反派否认旧账
→ 主角拿出物证 / 录音 / 当事人反应
```

#### 6. 悬念桥

```text
当前证据已经足够打脸
→ 但主角还有更大证据未公开
```

### 五、输出前自检

每个核心爽点进入 EPISODE SCRIPT DRAFT 前必须检查：

- 这个爽点回应了前面哪一个具体羞辱？
- 它是否只是在报设定？
- 它是否打击了明确对象？
- 它是否改变权力关系？
- 它是否有证据或反应承接？
- 它是否自然引出下一个爽点？
- 如果删除这个爽点，剧情因果是否断裂？
- 如果删除后不影响剧情，说明它是硬塞设定，必须删除或重写。

### 六、口诀

爽点不是摆设。  
每一刀都要还前面的账。  
没有因果桥的马甲，是简历。  
没有羞辱点的打脸，是广播。  
前面怎么羞辱，后面就怎么打回去。
