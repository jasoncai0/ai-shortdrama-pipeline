## 2. 工作流

### 全局流程锁

默认必须按 MODE 判断 → CONCEPT / 改编策略 → STORY_FRAMEWORK_LOCK → SERIES_ENGINE / PAYOFF_LADDER → EP01_DRAMA_BEAT_LOCK → CHARACTER_FUNCTION_MAP → WORLD_VISUAL_BIBLE → WORLD LOCK GATE → CHARACTER ASSET GENERATION PLAN → CHARACTER ASSET PACKAGE（CHARACTER @base → BASE CONFIRMATION GATE：必须用户确认 / user_confirmed=yes → 主角 / 重要角色 CHARACTER @sheet → SHEET LOCK GATE）→ LOCATION / PROP / COSTUME → EPISODE RELATION MAP → EPISODE SCRIPT DRAFT → SCENE BREAKDOWN → ACTION STATE / OPPONENT IDENTITY / EXTRAS CONTROL → SHOT UNIT → KEYFRAME → SEQUENTIAL I2V + Native Video Audio → VIDEO LOCK GATE → native audio failure recovery → RUNTIME STATE 执行。

禁止用户刚给题材 / 剧本就直接跳去做角色图。除非用户明确提供角色参考图、明确要求跳过世界设定，或已经给出等价 WORLD_VISUAL_BIBLE，否则不得跳步。

### STEP 1 —— 立项

**MODE A 原创｜CONCEPT LOCK**：写出爽点引擎类型（打脸逆袭 / 隐藏身份 / 重生复仇 / 先婚后爱 / 战神归来等，可多选）、爽感节拍（默认每 2–3 集中型爽点、每 8–12 集大爽点）、基调与人群。

**MODE B 改编｜源材料解析 + 改编策略**：详见 §2.5，这是改编的核心难点。

### STEP 2 —— 主线 / 切集

**MODE A｜SERIES MAP**：主线弧（开场钩子 → 压制累积 → 真相揭露 → 反攻 → 高潮打脸 → 收束）；集数地图（每集核心 State Delta）；效果聚焦——留存杠杆高度集中在前 3 集 + 卡点集，先把开篇钩子和首个大爽点打磨到极致，别平摊精力；卡点（仅 `iap_unlock` / `ad_unlock`，落在反转前一秒，`free` 则改设强完播钩子）；悬念栈（已埋未解 + 计划第几集消解，防烂尾）。

**MODE B｜重切集表**：见 §2.5。

### STEP 3 —— WORLD VISUAL BIBLE 世界视觉设定板（§4）【必须先锁】

产出 WORLD_VISUAL_BIBLE：固定信息板版式，用一张完整 16:9 横版图片解释整部剧的视觉系统。它不是单纯背景图，不是单一地点图，不是一组场景图，也不是普通 moodboard。它必须作为 AI 图像 / 视频生成模型的世界视觉宪法，用于锁定后续 prompt 编译、资产继承和关键帧生成的一致性。

WORLD VISUAL BIBLE 是全片最高世界资产。

它定义：

- 氛围基调
- 世界规则
- 主角成长方向
- 色彩系统
- 光影系统
- 场景方向
- 道具符号
- 动作语言
- 情绪曲线

核心要求：用户先要的是一张完整 16:9 横版定调图。

所以第一阶段只允许生成一张完整的 WORLD_VISUAL_BIBLE 综合信息板，不允许拆成一张张巷子、走廊、房间、色彩图、光影图、道具图。

门禁：WORLD VISUAL BIBLE 未锁定，不得进入 STEP 4。

### STEP 4 —— CHARACTER BASE 角色白底三视图全身基准图（§4）【人物生产真相源】

每个角色、每个重要成长阶段，必须先生成一张独立的 `CHAR_xxx@base_stage`：

- 默认 16:9 横版或 4:3 横版白底三视图图像
- 一张图内包含同一角色正面 / 侧面 / 背面三个完整全身视图
- 白底或浅灰底
- 三视图必须同一张脸、同一骨相、同一年龄感、同一身材比例
- 三视图必须同一套当前剧情合法基础服装
- 中性站姿
- 脸部清晰
- 发型清晰
- 服装从头到脚完整可见
- 无文字
- 无标签
- 无边框信息栏
- 无局部细节拼贴
- 无表情宫格
- 无角色卡信息栏
- 无场景背景

`CHAR_xxx@base` 是角色生产真相源。

后续角色卡、表情、关键帧、首尾帧、I2V 人物一致性都必须从它派生。

门禁：CHARACTER @base 未通过 BASE CONFIRMATION GATE 且未获得用户确认，不得进入 @sheet；主角 / 重要角色的角色资产包未完成，不得进入人物关键帧 / I2V。

### STEP 5 —— CHARACTER ASSET PACKAGE / 地点 / 道具 / 服装资产（§4）

`CHARACTER ASSET PACKAGE` 是主角 / 重要角色的完整角色设计阶段，不是单张 @base。

合法内部顺序固定为：

```text
1. CHAR_xxx@base_stage 白底三视图全身基准图
2. BASE CONFIRMATION GATE
   - Generated Image Exists = yes
   - Base image_id / asset_id / node_key exists
   - User Reviewed Image = yes
   - User Confirmed Image / user_confirmed = yes
3. CHAR_xxx@sheet 11 模块表演辅助设计表
4. SHEET CONFIRMATION GATE
5. CharacterAssetCompletion = base_and_sheet_complete
```

硬规则：

- `CHAR_xxx@base_stage` 未真实生成，不得进入 @sheet。
- `CHAR_xxx@base_stage` 未经用户确认 / `user_confirmed=yes`，不得生成 @sheet。
- BASE CONFIRMATION GATE 是进入 @sheet 的前置闸门，不是角色资产包的最终完成闸门。
- 主角 / 重要角色只有完成并确认 `@sheet` 后，角色资产包才算完成。
- 用户确认 @base 后，`Next Allowed Substage = CHARACTER @sheet`，系统不得再跳去 LOCATION / PROP / COSTUME 或分镜。

在对应角色资产包完成后，才允许继续生成：

- 表情 / 微表情 / 头部角度 / 姿态 / 近景 / 手部动作等 @sheet 内部表演辅助图块
- LOCATION 资产
- PROP 资产
- COSTUME 资产

删除旧口径：不得再输出独立“视角补充图 / 视角队列 / 正侧背补充图”作为角色资产名称；如需角度信息，只能写为 `head angle studies / posture library / cinematic close-up performance panels`，且必须属于 @sheet 的 MODULE 07 / MODULE 08 / MODULE 09，不得重新生成正侧背身份队列。

每个地点、道具、服装都作为独立资产生成，不能提前代替 WORLD_VISUAL_BIBLE。所有资产必须继承 WORLD VISUAL BIBLE 中对应模块。

严禁跳过 @base 直接生成 @sheet。  
严禁 @base 未确认就生成 @sheet。  
严禁把整张 @sheet 喂给视频模型。

### STEP 6 —— 单集关系图 / 可拆分脚本 / 逐集分镜（集 → 场 → SHOT UNIT）

续写前先读运行时状态（§3）。

进入分镜前，必须先完成：

```text
EPISODE RELATION MAP
→ EPISODE SCRIPT DRAFT
→ SCENE BREAKDOWN
→ SHOT UNIT
```

先明确本集人物关系、压迫关系、关系历史、Because / But / Therefore，再把本集拆成几场戏；每场写场景头部（§5.5）（场景目标 + 各角色当下目标 / 战术 / 阻碍 + 引用冲突线 + 关系显影方式 + 因果链）。

之后再按写作内核（§4.14）写戏与对白 → 过反无聊机制（§4.15） → 按节奏（§5）排镜 → 每镜按 SHOT UNIT 模板（§6）写、守 AI 视频约束（§4.16）与关系清晰度补丁（§0.4） → 末步编译英文 prompt。

禁止从 SERIES MAP 直接跳 SHOT UNIT。脚本不清，不得分镜。

### STEP 7 —— 红队 + 自检 + 更新状态

先跑 §4.15 的「划走点检测」，再跑 §7 自检清单，不过则回对应步骤重写；通过后更新运行时状态。

### STEP 8 —— 生产执行（§6.6，别停在文字！）

分镜与 prompt 不是终点。进入 §6.6 的生产执行循环：碎镜头打包成 VIDEO_GENERATION_TASK →〈闸门〉关键帧图 →〈闸门〉**按 VIDEO_GENERATION_TASK 顺序批量 I2V 生成**（一个 task = 一次视频工具调用 = 一个含多段碎镜头的视频文件；**禁止按 MICRO_SHOT_UNIT 逐条调用视频工具**，只有 batch 失败时才按 Fallback Split Plan 降级拆分），并优先让视频模型直接说中文对白 / OS →〈闸门〉原生音频失败则重生成当前 VIDEO_GENERATION_TASK（反复失败再降级拆分）。先判定 FAST_PROTOTYPE / PRODUCTION 两挡；实际出图出视频合成在所接工具里跑。

> 工具调用计数锁：视频工具调用次数 = VIDEO_GENERATION_TASK 数（90s 单集约 6-12 次），**不等于 MICRO_SHOT_UNIT 数（碎镜头数通常远多于 task 数）**。详见 §0.1J。
